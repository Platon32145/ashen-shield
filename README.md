# Пепельный Щит

Сайт средневековой гильдии стражей Minecraft RP: летопись, открытый склад и защищённый редактор. React 19, TypeScript, Vite, Supabase, PostgreSQL RLS.

## Быстрый запуск

Нужен Node.js 22 или новее.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://localhost:5173).
В Windows при проблемах с PowerShell используйте `npm.cmd` вместо `npm`.

Без переменных окружения включён **локальный предпросмотр**: демонстрационные запасы и текст сохраняются в localStorage браузера. Кнопка «Вход в архив» открывает явно обозначенный локальный редактор. Это демонстрация, доступная каждому посетителю, а не защищённая авторизация. Данные не передаются другим пользователям.

## Общий архив и настоящая админка

1. Создайте проект на https://supabase.com.
2. Откройте SQL Editor и выполните содержимое `supabase/migrations/001_archive.sql` один раз. Склад начнёт с нулевых остатков; каталог предметов уже встроен в сайт.
3. В Authentication → Users создайте пользователя через Add user и подтвердите email. Скопируйте UUID пользователя.
4. В SQL Editor назначьте роль `admin` командору:

```sql
insert into public.profiles(id, display_name, role)
values ('UUID-ПОЛЬЗОВАТЕЛЯ', 'Командор', 'admin');
```

Для сотрудника склада после выполнения `supabase/migrations/004_sklad_role.sql` используйте роль `Sklad`:

```sql
insert into public.profiles(id, display_name, role)
values ('UUID-ПОЛЬЗОВАТЕЛЯ', 'Интендант', 'Sklad');
```

5. Отключите публичную регистрацию в Authentication → Sign In / Providers → Allow new users to sign up.
6. Скопируйте `.env.example` в `.env.local`. Вставьте Project URL и **publishable/anon key** из Supabase Project Settings → API. Никогда не используйте service_role / secret key во фронтенде.
7. Перезапустите `npm run dev`.
8. Через «Вход в архив» войдите созданным email и паролем. На главной появится редактор текста, на складе количества станут кнопками.

Гостям доступно только чтение. `admin` может редактировать текст сайта, склад и рапорты. `Sklad` может изменять склад и создавать/читать рапорты, но не может редактировать текст сайта или читать журнал аудита. Изменения защищены RLS и SQL-функциями; назначить себе роль через браузер нельзя. Одновременное изменение одного остатка двумя сотрудниками обнаруживается по версии записи. Склад обновляется при возвращении во вкладку, раз в минуту и по кнопке обновления.

## Публикация на GitHub Pages

1. Создайте GitHub-репозиторий и загрузите содержимое этой папки (без node_modules, .env.local и dist). Основная ветка должна называться `main`.
2. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. Settings → Secrets and variables → Actions → Variables: добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Это публичные клиентские настройки; приватные ключи не нужны.
4. Отправьте изменения в `main` или запустите workflow вручную. Workflow проверит код, тесты, соберёт сайт и опубликует его.
5. Ссылка появится в Settings → Pages и в результате workflow. Работают и домен пользователя, и путь вида `https://user.github.io/repository/`: Vite использует относительные пути, страницы — hash-маршруты.

Если переменные не заданы, будет опубликован локальный предпросмотр. Для общего архива обязательно выполните настройку выше.

## Как пользоваться складом

- В каталоге **1384 предмета Minecraft Java 1.21.4**, поиск по русскому названию и `minecraft:id`.
- Категории, фильтр наличия, пять вариантов сортировки, страницы по 40 позиций, выгрузка текущей выборки в CSV.
- Все предметы доступны в каталоге сразу. Чтобы добавить предмет в запасы, задайте ненулевое количество. Чтобы убрать из наличия, задайте 0 — строка останется в полном каталоге.
- В админке нажмите на любую из трёх количественных колонок. Для стаков вводятся полные стаки и остаток, для сундуков — сундуки, стаки и остаток. Лишний остаток нормализуется автоматически.
- Двойной сундук — 54 слота. Учитываются стаки по 64, 16 и 1.
- 84 обычных предмета = 1 стак + 20 шт. = 0 двойных сундуков + 1 стак + 20 шт.
- Сохраняется только итог в штуках, остальные значения вычисляются. Допустимый диапазон: 0–1 000 000 000, только целые числа.
- Фильтры записываются в URL — можно отправить ссылку другому игроку.

## Журнал изменений

### Рапорты и складские отчёты

В существующей базе выполните `supabase/migrations/003_reports.sql` через SQL Editor **после** предыдущих миграций, затем `supabase/migrations/004_sklad_role.sql`. Последняя добавляет роль `Sklad` и права сотрудника склада. Миграция `003` создаёт таблицу `reports` и обновляет функцию сохранения склада: количество и рапорт записываются одной транзакцией. Без этих миграций новая версия складского редактора не сохранит изменения.

В режиме `admin` или `Sklad` появляется вкладка «Отчёты и рапорты» (поиск, страницы по 50 записей) и кнопка «Отправить рапорт». Последняя запись показывается на главной всем посетителям. При изменении количества автоматически создаётся приходный или расходный отчёт по **разнице** между старым и новым количеством, а не по всему остатку. Каждое сохранение строки — отдельный рапорт. Нулевое изменение рапорта не создаёт. Сундуки, стаки и штуки выводятся без нулевых единиц. Время — МСК. На устройстве автора главная обновляется после сохранения; другие открытые вкладки проверяют последний рапорт раз в 5 секунд.

Имя и звание задайте одним полем `profiles.display_name`, например `Командор Мару` или `Интендант` (Table Editor → profiles). Если оно пустое, используется `full_name`/`name` из Authentication → Users → User metadata. Подпись: `Командор Мару — ГИЛЬДИЯ СТРАЖЕЙ` (вторая часть настраивается в редакторе сайта). После смены имени обновите сайт или войдите заново. Автор автоматических рапортов определяется сервером, а не передаётся браузером. История рапортов доступна `admin` и `Sklad`, последний рапорт публичен.

Если база создана по первой версии проекта и редактор не сохраняет текст, выполните `supabase/migrations/002_fix_content_save.sql` в Supabase SQL Editor. Файл исправляет триггер журнала (обращение к отсутствующему полю item_id у site_content) и увеличивает допустимый размер настроек расширенного редактора. Существующие данные сохраняются; повторно запускать 001_archive.sql не нужно.

Изменения текста и запасов автоматически записываются в `audit_log` (пользователь, старое/новое значение, время). Таблица доступна администратору в Supabase Table Editor; гостям журнал закрыт. Не редактируйте audit_log вручную.

## Команды

```sh
npm run dev       # разработка
npm run build     # TypeScript + production-сборка в dist/
npm run preview   # просмотр production-сборки
npm run lint      # проверка кода
npm test          # тесты пересчёта
npm run catalog   # пересоздание каталога и загрузка недостающих текстур
```

При сетевых ограничениях можно установить зависимости через доступное зеркало: `npm ci --registry=https://registry.npmmirror.com`. Готовый каталог включён в репозиторий, загружать его для запуска не требуется.

## Файлы

- `src/App.tsx` — главная, склад, авторизация, редакторы.
- `src/styles.css` — адаптивная графитово-бронзовая тема.
- `src/lib/quantity.ts` — расчёты и проверка значений.
- `src/lib/store.ts` — Supabase, стартовые тексты, локальные данные.
- `src/data/items.json` — справочник предметов.
- `public/items/` — локальные PNG-текстуры.
- `supabase/migrations/001_archive.sql` — схема, роли, политики и журнал.
- `.github/workflows/pages.yml` — проверка и публикация.

Название гильдии (шапка, подвал, вкладка браузера), заголовки, девизы, подписи, тексты склада и описания кодекса меняются через «Редактировать сайт» после входа. В редакторе раскройте «Оформление и подписи сайта» и используйте поиск. Старые записи автоматически дополняются новыми полями; повторно выполнять SQL не нужно. Герб и favicon находятся в `public/crest.svg`. Основные цвета определены в начале `src/styles.css`, тёмные полосы прокрутки и анимации — в `src/enhancements.css`. Анимации учитывают системную настройку уменьшения движения.

Подробная инструкция для новичков сохранена в файле `Гайд — Supabase и GitHub.txt`.

## Дизайн и источники

Направление утверждено в плане проекта: геральдический реестр крепости, тёмный графит, бронза, картографическая сетка, сдержанный интерфейс учёта. Правила читабельности, ролей цветов, focus-visible и адаптивности взяты из bundled references навыка refero-design. Lucide используется как единый набор UI-иконок, герб — авторский SVG.

Для некоторых технических предметов и блоков без отдельной текстуры показана нейтральная пиктограмма коробки; это не мешает учёту. 881 текстура поставляется локально.
